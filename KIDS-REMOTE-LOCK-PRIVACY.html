1. Scope and contact

This policy describes KIDS REMOTE LOCK for Android and its companion Windows child receiver, based on the current local implementation. It covers parent and child device roles. Schedules, individual app blocking, allowed-app lists and usage statistics are Android features. Windows provides session blocking, timers, rewards, extra-time requests and profiles; it does not read a Windows program inventory or record program-use statistics. The developer is Łukasz Bednarski, publishing as VAIPER998. Privacy questions and requests: lukaszbednarski998@interia.pl.

2. Local operation and recipients

The app has no developer-operated account service, cloud storage or central control server. Parental commands and device snapshots are exchanged directly between paired devices on the same local network. Remote control outside that network over mobile data is not provided. The paired parent receives the child device's status and, when requested, its rules, visible app inventory, recorded daily usage totals and extra-time request. These transfers are necessary for the parental-control features and are not sent to the developer. The lock-all and unlock-all buttons send a separate command to each paired device. Offline devices do not receive a deferred cloud command; no developer server stores these commands.

3. Information processed

  • Pairing and connection: a randomly generated device identifier, pairing key, device model or computer name, local IP address, network port and pairing status. The QR code contains connection details and the secret pairing key.
  • Profiles and rules: child and device labels entered by the parent, schedules, selected blocked and allowed app package names, lock status, timers, rewards and schedule overrides.
  • Android app information: names and package identifiers of apps visible through Android's launcher-app query, whether an app is a game, and the identity of default phone/SMS apps needed for exceptions.
  • Android daily use: the foreground app package, approximate durations per app, total recorded daily use and game-time totals. Measurement occurs while the child service runs, the screen is interactive and unlocked, and app use is permitted by the rules. Blocked intervals are excluded; these totals are not a complete system-wide usage history. It does not import earlier usage history.
  • Time requests: selected duration, random request identifier, creation time and the parent's approve/deny decision. A pending request may also appear in a notification on the parent's device.
  • Protection and preferences: a salted PBKDF2 hash of the parent PIN, language preference, protection state and local settings. The plain PIN is not persistently stored by the app.
  • Trial and purchases: install time, trial deadlines, highest observed clock time, expiry and purchase-entitlement state. Android's app-scoped ANDROID_ID is used locally as an input to a hash protecting trial records; the app does not send it to the developer or paired parent. Google Play purchase tokens are processed to acknowledge purchases through Google Play.

4. AccessibilityService disclosure

KIDS REMOTE LOCK uses Android AccessibilityService for parental control, not as a disability accessibility tool. With the parent's disclosure acceptance and manual Android service activation, it observes window-state events and their app package names to identify the foreground app, display parental block screens, apply schedules and app rules, keep communication apps available, protect relevant settings and record approximate app-use durations. It can operate in the background while enabled.

The service is configured with canRetrieveWindowContent=false. This implementation does not retrieve screen-node content, read message text, passwords or typed text, or record screens. Foreground app identifiers and use durations are personal device information and are processed as described above. The parent can disable protection and the service; when restrictions become inactive after trial expiry, the running receiver stops applying them.

5. Permissions and device administration

The camera is used to scan the pairing QR code; the app does not save or upload camera images. Network access supports local pairing and control and Google Play billing. Notification permission supports time-request notifications, which require the parent's app process and a local connection. Optional Device Administrator activation supports parental uninstall protection and can be removed by the parent. It does not give the developer remote access. The app opens the system dialer and leaves default phone/SMS communication available; it does not request access to contacts, SMS contents, call history, microphone or GPS location. Windows uses app PIN protection and operating-system account permissions, not Android AccessibilityService.

6. Google Play, advertising and third parties

The Android app offers a 60-minute trial and a one-time full-version purchase. Google Play handles purchase, restore and acknowledgement operations under Google's privacy policy. The developer does not receive card details through the app. Billing may require internet access even though parental control uses the local network. The current implementation contains no advertising SDK, developer analytics or automatic developer crash-reporting service. Local family data is not sold or sent for advertising. There is no developer-side purchase-validation server in this implementation.

7. Security

Local command and snapshot frames use authenticated AES-256-GCM encryption with the pairing key. The parent PIN is stored as a salted PBKDF2 hash. Network discovery uses unencrypted local UDP messages exposing the random receiver identifier and listening port; IP addresses are also visible on the local network. Discovery messages do not contain the pairing key, PIN or app-use statistics. On Windows, the stored pairing key is protected with Windows DPAPI for the current user account. Other local settings and statistics rely on operating-system storage protections; the app does not encrypt all stored data at rest. Keep devices and PINs secure and do not share pairing QR codes, screenshots or keys. These controls do not guarantee protection against an administrator, root access, device reset, process termination or a compromised device.

8. Retention and deletion

Pairing, profiles, PIN hashes, trial/purchase state and rules remain locally until changed or cleared. Android statistics keep the current observed day's totals; a new day replaces that record when the service next updates it. Android requests become inactive after 24 hours; the last request may remain in local storage until replaced or cleared. Windows stores the last request and its decision until replaced, unpaired or its local profile is removed. There is no developer cloud copy to delete.

Removing pairing on a connected child clears its family rules, usage totals and request and rotates its key; some local setup, PIN and trial records remain. The parent can remove device profiles locally. To remove all app data, first use the parent controls to release restrictions and deactivate the service/device administrator, then clear Android app storage or uninstall. Android backup is disabled in the current manifest. On Windows, uninstalling the program may leave its local profile at %LOCALAPPDATA%\KidsRemoteLock; after releasing restrictions and closing the receiver, delete that folder to erase the remaining profile. A trial expiry releases restrictions; it does not itself erase all data.

9. Children, parental responsibility and rights

This is a parent-managed tool used on a child's device with authorization from a parent or legal guardian. It is not intended for covert monitoring. The parent chooses labels and rules, controls access to the paired devices, and should explain the service to the child in an age-appropriate way. Avoid entering unnecessary sensitive information into labels. No child account or direct child registration with the developer is required.

Parents can inspect and change local information and delete it using the controls above. Where applicable, privacy rights may include access, correction, deletion, restriction, portability, objection, withdrawal of consent where applicable, and a complaint to the competent supervisory authority, including the Polish Personal Data Protection Office (UODO). Contact the developer for information processed by the developer; the developer cannot remotely inspect or delete family data held only on your devices. If you contact support, the developer processes the address, message and attachments you voluntarily send to respond, based on handling your request or a legitimate interest in support. Do not send a PIN or pairing key. Support correspondence is kept while needed for the request and related records, subject to applicable requirements; request deletion by email.

2. Działanie lokalne i odbiorcy danych

Aplikacja nie ma prowadzonego przez dewelopera serwisu kont, chmury ani centralnego serwera sterowania. Polecenia i informacje o urządzeniu są przesyłane bezpośrednio między sparowanymi urządzeniami w tej samej sieci lokalnej. Sterowanie poza tą siecią przez internet komórkowy nie jest dostępne. Sparowany rodzic otrzymuje stan urządzenia dziecka oraz, po wywołaniu odpowiedniej funkcji, jego zasady, listę widocznych aplikacji, zapisane dzienne czasy użycia i prośbę o dodatkowy czas. Te transfery służą kontroli rodzicielskiej; dane nie są wysyłane do dewelopera. Przyciski blokowania i odblokowania wszystkich urządzeń wysyłają osobne polecenie do każdego sparowanego odbiornika. Urządzenie offline nie otrzymuje odroczonego polecenia z chmury; serwer dewelopera nie przechowuje takich poleceń.

3. Przetwarzane informacje

  • Parowanie i połączenie: losowy identyfikator urządzenia, klucz parowania, model urządzenia lub nazwa komputera, lokalny adres IP, port i stan parowania. Kod QR zawiera dane połączenia i tajny klucz parowania.
  • Profile i zasady: wpisane przez rodzica nazwy dziecka i urządzenia, harmonogramy, identyfikatory blokowanych i dozwolonych aplikacji, stan blokady, timery, nagrody i czasowe wstrzymanie harmonogramów.
  • Aplikacje Androida: nazwy i identyfikatory aplikacji widocznych w zapytaniu o aplikacje uruchamiane z ekranu głównego, informacja o grze oraz domyślne aplikacje telefonu i SMS potrzebne do wyjątków.
  • Dzienne użycie Androida: identyfikator aplikacji na pierwszym planie, przybliżone czasy poszczególnych aplikacji, łączny zarejestrowany czas i suma czasu gier. Pomiar działa podczas pracy usługi dziecka, gdy ekran jest aktywny i odblokowany, a reguły pozwalają na używanie aplikacji. Okresy blokady są pomijane; nie jest to pełna systemowa historia użycia. Nie pobiera wcześniejszej historii użycia.
  • Prośby o czas: wybrana długość, losowy identyfikator, czas utworzenia i decyzja rodzica. Oczekująca prośba może pojawić się w powiadomieniu na urządzeniu rodzica.
  • Ochrona i ustawienia: skrót PIN-u rodzica z solą, utworzony przez PBKDF2, język, stan ochrony i ustawienia lokalne. Aplikacja nie zapisuje trwale PIN-u w jawnej postaci.
  • Trial i zakup: czas instalacji, termin trialu, najwyższy zaobserwowany czas zegara, wygaśnięcie i stan uprawnienia do pełnej wersji. Identyfikator Androida ANDROID_ID, o zakresie aplikacji, jest lokalnym składnikiem skrótu chroniącego zapis trialu; aplikacja nie przesyła go deweloperowi ani sparowanemu rodzicowi. Tokeny zakupu Google Play są przetwarzane do potwierdzenia zakupu w Google Play.

4. Ujawnienie użycia AccessibilityService

KIDS REMOTE LOCK korzysta z Android AccessibilityService do kontroli rodzicielskiej, a nie jako narzędzie wspierające osoby z niepełnosprawnościami. Po akceptacji informacji przez rodzica i ręcznym włączeniu usługi w Androidzie obserwuje zdarzenia zmiany okna i identyfikatory aplikacji. Pozwala to rozpoznać aplikację na pierwszym planie, wyświetlić blokadę rodzicielską, zastosować harmonogramy i reguły, pozostawić dostęp do komunikacji, chronić odpowiednie ustawienia oraz mierzyć przybliżony czas użycia. Włączona usługa może działać w tle.

Usługa ma ustawienie canRetrieveWindowContent=false. Obecna implementacja nie pobiera treści elementów ekranu, nie czyta wiadomości, haseł ani wpisywanego tekstu i nie nagrywa ekranu. Identyfikatory aplikacji oraz czas użycia są informacjami o urządzeniu i są przetwarzane zgodnie z opisem powyżej. Rodzic może wyłączyć ochronę i usługę; po wygaśnięciu trialu działający odbiornik przestaje stosować blokady.

5. Uprawnienia i administrator urządzenia

Aparat służy do skanowania QR parowania; aplikacja nie zapisuje ani nie przesyła obrazów aparatu. Dostęp do sieci obsługuje lokalne parowanie, sterowanie i płatności Google Play. Uprawnienie powiadomień służy prośbom o czas; ich odbiór wymaga działania procesu rodzica i lokalnego połączenia. Opcjonalny administrator urządzenia wspiera rodzicielską ochronę przed odinstalowaniem i może zostać usunięty przez rodzica. Nie daje deweloperowi zdalnego dostępu. Aplikacja otwiera systemowy telefon i pozostawia dostęp do domyślnego telefonu/SMS; nie żąda odczytu kontaktów, treści SMS, historii połączeń, mikrofonu ani lokalizacji GPS. Windows używa PIN-u aplikacji i uprawnień kont systemowych, a nie Android AccessibilityService.

6. Google Play, reklamy i inne podmioty

Aplikacja Android oferuje trial 60 minut i jednorazowy zakup pełnej wersji. Google Play obsługuje zakup, przywracanie i potwierdzanie zgodnie z polityką prywatności Google. Deweloper nie otrzymuje przez aplikację danych karty. Płatności mogą wymagać internetu, mimo że kontrola rodzicielska używa sieci lokalnej. Obecna implementacja nie zawiera SDK reklam, analityki dewelopera ani automatycznego wysyłania raportów awarii do dewelopera. Dane rodziny nie są sprzedawane ani przesyłane na potrzeby reklamy. Nie ma serwera dewelopera weryfikującego zakupy.

7. Bezpieczeństwo

Polecenia i odpowiedzi w sieci lokalnej korzystają z uwierzytelnionego szyfrowania AES-256-GCM przy użyciu klucza parowania. PIN jest zapisany jako skrót PBKDF2 z solą. Wykrywanie urządzeń używa nieszyfrowanych lokalnych wiadomości UDP z losowym identyfikatorem odbiornika i portem; adresy IP są również widoczne w sieci lokalnej. Wiadomości wykrywania nie zawierają klucza parowania, PIN-u ani statystyk użycia. Na Windows zapisany klucz parowania jest chroniony przez Windows DPAPI dla bieżącego konta użytkownika. Pozostałe ustawienia i statystyki korzystają z systemowej ochrony pamięci; aplikacja nie szyfruje wszystkich danych zapisanych na dysku. Chroń urządzenia i PIN, nie udostępniaj kodów QR, ich zrzutów ani kluczy. Nie jest to gwarancja odporności na administratora, root, reset, zatrzymanie procesu lub przejęcie urządzenia.

8. Przechowywanie i usuwanie

Parowanie, profile, skrót PIN-u, dane trialu/zakupu i reguły pozostają lokalnie do zmiany lub usunięcia. Statystyki Androida obejmują bieżący zaobserwowany dzień; po zmianie dnia zapis zostaje zastąpiony przy następnym pomiarze usługi. Prośba Androida staje się nieaktywna po 24 godzinach; ostatni zapis może pozostać do zastąpienia lub usunięcia. Windows przechowuje ostatnią prośbę i decyzję do zastąpienia, usunięcia parowania lub usunięcia lokalnego profilu. Nie ma kopii danych rodziny w chmurze dewelopera.

Usunięcie parowania z połączonego urządzenia dziecka usuwa jego reguły rodziny, statystyki i prośbę oraz zmienia klucz; część ustawień, PIN i trial pozostają. Rodzic może usunąć lokalne profile urządzeń. Aby usunąć wszystkie dane, najpierw odblokuj urządzenie i wyłącz usługę/administratora przez ustawienia rodzica, następnie wyczyść pamięć aplikacji Android lub odinstaluj ją. Kopia zapasowa Androida jest wyłączona w obecnym manifeście. Na Windows odinstalowanie może pozostawić profil w %LOCALAPPDATA%\KidsRemoteLock; po odblokowaniu i zamknięciu odbiornika usuń ten folder, aby usunąć resztę profilu. Wygaśnięcie trialu dezaktywuje blokady, ale samo nie usuwa wszystkich danych.

9. Dzieci, odpowiedzialność rodzica i prawa

Jest to narzędzie zarządzane przez rodzica na urządzeniu dziecka, za zgodą rodzica lub opiekuna prawnego. Nie służy ukrytemu monitorowaniu. Rodzic wybiera nazwy i reguły, chroni dostęp do sparowanych urządzeń i powinien wyjaśnić działanie dziecku odpowiednio do wieku. Nie wpisuj zbędnych danych wrażliwych w nazwy profili. Aplikacja nie wymaga konta dziecka ani jego rejestracji u dewelopera.

Rodzice mogą przeglądać, poprawiać i usuwać lokalne dane opisanymi metodami. W odpowiednich przypadkach prawa mogą obejmować dostęp, sprostowanie, usunięcie, ograniczenie, przenoszenie danych, sprzeciw, wycofanie zgody w odpowiednich przypadkach oraz skargę do właściwego organu nadzorczego, w Polsce Prezesa Urzędu Ochrony Danych Osobowych (UODO). W sprawie danych przetwarzanych przez dewelopera skontaktuj się e-mailem; deweloper nie może zdalnie odczytać ani usunąć danych rodziny znajdujących się wyłącznie na Twoich urządzeniach. Przy kontakcie z pomocą deweloper przetwarza dobrowolnie przekazane adres, wiadomość i załączniki w celu odpowiedzi, na podstawie obsługi żądania lub uzasadnionego interesu pomocy użytkownikom. Nie wysyłaj PIN-u ani klucza parowania. Korespondencja jest przechowywana przez czas potrzebny do obsługi sprawy i związanej dokumentacji, z uwzględnieniem obowiązujących wymogów; o usunięcie poproś e-mailem.
