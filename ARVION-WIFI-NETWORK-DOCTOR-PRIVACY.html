Privacy Policy — ARVION WiFi & Network Doctor

Date: October 11, 2026

ARVION WiFi & Network Doctor is a network diagnostic utility. The app does not require an account and contains no advertising.

Local network data

The app may read current connection parameters, IP addresses, DNS information, Wi-Fi information, and results of scans performed on the user's local network. These data are used for diagnostics and processed locally on the device. ARVION does not upload LAN scan results to its own server.

Location permission

Android requires precise location permission for Wi-Fi scan results (startScan() / getScanResults()). ARVION uses this permission only to obtain Wi-Fi scan results. The app does not determine, store, or transmit the user's physical location.

Internet tests

When the user starts diagnostics or a speed test, the app makes technical test connections to public Internet services, including Google/Gstatic, Cloudflare/1.1.1.1, and example.com. The user's IP address is inherently visible to the servers contacted, subject to those providers' own privacy policies.

Google Play purchases

The full-version purchase is processed by Google Play Billing. ARVION receives purchase-state information required to verify and restore the license. Payment-card information is not handled directly by the app.

Reports and monitoring

PDF and CSV reports are stored only in a location selected by the user. Speed-test and Wi-Fi signal histories are stored locally in private app storage. Signal samples may contain SSID, BSSID, frequency, RSSI and measurement time. The user decides whether to export these data. If the optional background monitor is enabled, the app stores a local set of known IP addresses to detect newly appearing devices.

Ads and subscriptions

The app contains no ads and no subscriptions. The full version is unlocked by a one-time purchase.

Local Wi-Fi credential vault If you choose to use the Wi-Fi credential vault, ARVION stores only credentials that you explicitly enter. The vault is encrypted locally with AES-GCM using a non-exportable Android Keystore key. ARVION does not read passwords saved by Android and does not transmit vault contents to ARVION servers.

Privacy Shield local history Privacy Shield can store a local history of BLE scan results and network-camera candidates so the user can mark entries as watched, known, or ignored. This history (including first/last seen time, detection count, signal level when available, and technical detection evidence) is stored only in the app's private local storage and is not uploaded by ARVION. A detection is heuristic and is not proof that a person is tracking, recording, or spying on the user.

Local HTTP and router tools Some router administration interfaces, OpenWrt ubus, local file transfer and user-configured monitoring targets may use plain HTTP on the local/private network because the target device itself does not provide HTTPS. ARVION only uses such cleartext connections when required by a selected local-network feature or a URL explicitly chosen by the user. Credentials are never sent to a non-private host by the router-integration module.

App backup Android application backup includes only the language preference and two copies of trial state. Diagnostic history, purchase entitlement, pairing tokens and vault data are excluded. Backup availability depends on Android settings and its backup mechanism. Trial state includes the installation timestamp, highest observed timestamp and expiry flag. Local integrity checking binds it to the app package and Android ID; the app does not upload this identifier to an ARVION server.

Bluetooth, camera and device sensors Privacy Shield may use Bluetooth scanning to discover nearby BLE advertisements after the user grants the required Nearby devices/Bluetooth permission. The optional camera/IR helper uses the device camera only while the user opens that tool. The optional EMF-style helper reads the device magnetometer when available. ARVION does not upload camera frames, BLE scan history or sensor readings to ARVION servers.

Usage access The optional Data Usage Monitor uses Android's system NetworkStatsManager. Android requires the user to grant special Usage Access before per-app network statistics can be read. ARVION uses those statistics locally to display Wi-Fi/mobile usage and optional local threshold alerts.

Remote administration tools SSH, SFTP, Telnet, SNMP and router-administration features connect only to hosts selected or configured by the user. Credentials entered for a session are used to establish that requested connection. Telnet and some legacy local router interfaces are not encrypted; the app displays warnings where applicable.

Windows Agent If the user pairs ARVION Network Agent on a Windows computer, Android communicates with that computer over the local network. Pairing uses an Agent-generated bearer token and certificate pinning. The Agent stores its own local monitoring history on that Windows computer. ARVION does not operate a relay server for Agent traffic.

External lookup/update services Optional functions may contact external infrastructure selected by the feature, such as DNS/DoH resolvers, WHOIS/ASN services, public speed-test endpoints, or IEEE registry sources used to update the local OUI manufacturer database. The remote service can inherently observe the user's public IP address and the technical request sent to it. ARVION does not use these requests to build an advertising profile.

Optional NDT7 / M-Lab tests NDT7 runs only after the user selects M-Lab and confirms its separate notice. M-Lab publishes measurement data including the public IP address under its privacy policy. The test can transfer substantial data over roughly ten seconds per direction. Short-lived server-selection tokens are used only for that connection and are not stored in ARVION history. Cloudflare remains an alternative provider.

Imported plans, SSH keys and local credentials Imported floor plans are copied into private app storage; selected PNG/CSV exports are created only at a user-selected destination. SSH passwords, pasted private keys and key passphrases stay in session memory and are not persisted by ARVION. Command snippets may contain user-entered text and are stored locally. Agent pairing credentials are encrypted with an Android Keystore-backed AES-GCM key. Wi-Fi vault access additionally uses a system-authentication UI gate and screenshot protection; its key is not configured to demand biometric authentication for each cryptographic operation. Copied passwords are marked sensitive where supported and cleared after thirty seconds only if they remain the current clipboard value.

The optional terminal lock uses Android biometric or device-credential authentication. Biometric templates are managed by Android and are not read by ARVION. Windows vendor registry updates contact IEEE only when the user requests the update.

Developer and privacy contact This policy applies to ARVION WiFi & Network Doctor (Android package pl.arvion.wifinetworkdoctor) and the optional ARVION Network Agent. Developer: Łukasz Bednarski / ARVION. For privacy questions or requests, contact lukaszbednarski998@interia.pl. This app has no ARVION user account, advertising SDK or behavioral analytics service.

Retention and deletion Diagnostic histories, device profiles, saved targets, command snippets, imported plans, vault entries and Agent pairing data stay in local storage until removed through the relevant tool or until the app's storage is cleared. Some histories have bounded rolling retention and replace older entries. To delete all Android-local data, use Android Settings → Apps → ARVION WiFi & Network Doctor → Storage → Clear storage. Clearing storage also removes locally stored credentials. Exported files remain at your chosen destination and must be deleted there separately. Android backup may retain the language preference and trial state according to your backup settings; manage or delete those backups through Android/Google backup settings. Uninstalling the Android app does not delete data on a paired Windows computer. To remove Windows Agent data, stop the Agent and delete its local data directory %LOCALAPPDATA%\ARVION\NetworkAgent; confirm the directory used by the Agent before deleting it. Google Play retains purchase/payment records under Google's policies. Previously published M-Lab measurements are not deleted by clearing this app. Contact the respective external provider about data that it retains.

External recipients and secure handling Public connectivity tests, DNS/DoH, IP/domain lookups, vendor updates and user-requested transfers necessarily send requests to their respective endpoints. These endpoints receive the public IP address and request contents needed for that operation. ARVION does not sell local scan results or upload them to an ARVION cloud. Requests and credentials sent to user-selected hosts are controlled by the user. HTTPS, SSH/SFTP and pinned Agent TLS provide transport protection where supported; Telnet and selected local HTTP tools are unencrypted. Exported reports can contain network identifiers and should be shared deliberately.

Provider privacy information: Google, Cloudflare, M-Lab and IEEE. Other user-selected services apply their own policies. If you email support, the developer receives your email address and the contents or attachments you choose to send. These are used to respond to your request and investigate reported issues; ask the contact above to delete correspondence when it is no longer needed, subject to applicable record-retention obligations.

Intended use and policy changes The app is a general network utility and is not specifically directed at children. Use scanning and administration tools only on networks and devices you are authorized to access. Changes to this policy will be published on this page with an updated date.

Polityka prywatności — ARVION WiFi & Network Doctor

Data: 11 października 2026 r.

ARVION WiFi & Network Doctor jest narzędziem diagnostycznym sieci. Aplikacja nie wymaga zakładania konta i nie zawiera reklam.

Dane sieci lokalnej

Aplikacja może odczytywać parametry bieżącego połączenia, adresy IP, DNS, informacje o Wi-Fi oraz wyniki skanowania urządzeń w lokalnej sieci. Dane te są wykorzystywane do diagnostyki i są przetwarzane lokalnie na urządzeniu. Wyniki skanów nie są wysyłane przez ARVION na własny serwer.

Uprawnienie lokalizacji

Android wymaga uprawnienia do dokładnej lokalizacji dla wyników skanowania Wi-Fi (startScan() / getScanResults()). ARVION wykorzystuje to uprawnienie wyłącznie w celu uzyskania wyników Wi-Fi. Aplikacja nie ustala, nie zapisuje i nie przesyła fizycznego położenia użytkownika.

Testy internetowe

Po uruchomieniu przez użytkownika diagnostyki lub testu prędkości aplikacja wykonuje techniczne połączenia testowe do publicznych usług internetowych, m.in. Google/Gstatic, Cloudflare/1.1.1.1 oraz example.com. Adres IP użytkownika jest z natury widoczny dla serwerów, z którymi nawiązywane jest połączenie, na zasadach ich własnych polityk prywatności.

Zakupy Google Play

Zakup pełnej wersji jest obsługiwany przez Google Play Billing. ARVION otrzymuje od Google Play informacje potrzebne do sprawdzenia stanu zakupu i przywrócenia licencji. Dane płatnicze użytkownika nie są obsługiwane bezpośrednio przez aplikację.

Raporty i monitoring

Raporty PDF i CSV są zapisywane wyłącznie w lokalizacji wybranej przez użytkownika. Historia testów prędkości i sygnału Wi-Fi jest przechowywana lokalnie w prywatnej pamięci aplikacji. Próbki sygnału mogą zawierać SSID, BSSID, częstotliwość, poziom RSSI i czas pomiaru. Użytkownik sam decyduje o eksporcie tych danych. Po opcjonalnym włączeniu monitoringu aplikacja przechowuje lokalnie listę znanych adresów IP, aby wykrywać pojawienie się nowych urządzeń.

Reklamy i subskrypcje

Aplikacja nie zawiera reklam ani subskrypcji. Pełna wersja jest odblokowywana jednorazowym zakupem.

Lokalny sejf danych Wi-Fi Jeżeli korzystasz z sejfu danych Wi-Fi, ARVION zapisuje wyłącznie dane wpisane przez Ciebie. Sejf jest lokalnie szyfrowany AES-GCM kluczem nieeksportowalnym z Android Keystore. ARVION nie odczytuje haseł zapisanych przez system Android i nie wysyła zawartości sejfu na serwery ARVION.

Lokalna historia Privacy Shield Privacy Shield może zapisywać lokalną historię wyników skanowania BLE i kandydatów na kamery sieciowe, aby użytkownik mógł oznaczać wpisy jako obserwowane, znane lub ignorowane. Historia (w tym czas pierwszego/ostatniego wykrycia, liczba wykryć, poziom sygnału jeśli jest dostępny oraz techniczne przesłanki wykrycia) jest przechowywana wyłącznie w prywatnej pamięci aplikacji i nie jest wysyłana przez ARVION. Wykrycie ma charakter heurystyczny i nie jest dowodem, że ktoś śledzi, nagrywa lub szpieguje użytkownika.

Lokalny HTTP i narzędzia routera Niektóre panele administracyjne routerów, OpenWrt ubus, lokalny transfer plików oraz cele monitoringu wskazane przez użytkownika mogą korzystać ze zwykłego HTTP w sieci lokalnej/prywatnej, ponieważ samo urządzenie docelowe nie udostępnia HTTPS. ARVION używa takiego połączenia tylko wtedy, gdy wymaga go wybrana funkcja sieci lokalnej albo adres URL podany przez użytkownika. Moduł integracji routera nie wysyła danych logowania do hosta spoza sieci prywatnej.

Kopie zapasowe aplikacji Systemowa kopia zapasowa Android obejmuje wyłącznie ustawienie języka oraz dwie kopie stanu triala. Lokalna historia diagnostyczna, stan uprawnienia zakupu, tokeny parowania i dane sejfu nie są objęte tą kopią. Dostępność kopii zależy od ustawień i mechanizmu Androida. Stan triala zawiera czas instalacji, najwyższy zaobserwowany czas i znacznik wygaśnięcia. Lokalna kontrola integralności wiąże go z pakietem aplikacji i identyfikatorem Android ID; aplikacja nie przesyła tego identyfikatora na serwer ARVION.

Bluetooth, kamera i czujniki urządzenia Privacy Shield może korzystać ze skanowania Bluetooth w celu wykrywania pobliskich reklam BLE po nadaniu przez użytkownika wymaganych uprawnień Bluetooth/Urządzenia w pobliżu. Opcjonalne narzędzie kamera/IR używa aparatu tylko podczas otwarcia tej funkcji. Opcjonalny moduł EMF korzysta z magnetometru urządzenia, jeśli jest dostępny. ARVION nie wysyła na własne serwery obrazu z kamery, historii BLE ani odczytów czujników.

Dostęp do danych użycia Opcjonalny Data Usage Monitor korzysta z systemowego NetworkStatsManager Androida. Android wymaga, aby użytkownik sam nadał specjalny dostęp Usage Access przed odczytem statystyk sieciowych poszczególnych aplikacji. ARVION wykorzystuje te dane lokalnie do prezentacji zużycia Wi-Fi/danych komórkowych i opcjonalnych lokalnych alertów limitu.

Narzędzia zdalnej administracji Funkcje SSH, SFTP, Telnet, SNMP oraz administracji routerem łączą się wyłącznie z hostami wskazanymi lub skonfigurowanymi przez użytkownika. Dane logowania wpisane dla sesji są używane do zestawienia żądanego połączenia. Telnet oraz część starszych lokalnych interfejsów routerów nie są szyfrowane; aplikacja wyświetla stosowne ostrzeżenia.

Windows Agent Jeżeli użytkownik sparuje ARVION Network Agent na komputerze z Windows, aplikacja Android komunikuje się z tym komputerem przez sieć lokalną. Parowanie wykorzystuje token wygenerowany przez Agenta oraz pinning certyfikatu. Agent przechowuje własną lokalną historię monitoringu na tym komputerze. ARVION nie używa serwera pośredniczącego do ruchu Agenta.

Zewnętrzne usługi lookup/aktualizacji Opcjonalne funkcje mogą łączyć się z zewnętrzną infrastrukturą właściwą dla danego narzędzia, np. resolverami DNS/DoH, usługami WHOIS/ASN, publicznymi endpointami testów prędkości albo rejestrami IEEE służącymi do aktualizacji lokalnej bazy producentów OUI. Taka usługa z natury może zobaczyć publiczny adres IP użytkownika oraz techniczne zapytanie. ARVION nie wykorzystuje tych połączeń do tworzenia profilu reklamowego.

Opcjonalny NDT7 / M-Lab Test działa po wybraniu M-Lab i potwierdzeniu osobnego komunikatu. M-Lab publikuje dane pomiaru wraz z publicznym adresem IP zgodnie ze swoją polityką prywatności. Około dziesięciosekundowy transfer w każdym kierunku może zużywać dużo danych. Krótkotrwałe tokeny wyboru serwera służą tylko połączeniu i nie są zapisywane w historii ARVION. Alternatywą pozostaje Cloudflare.

Plany, klucze SSH i dane dostępowe Importowany plan jest kopiowany do prywatnego folderu aplikacji; PNG/CSV są eksportowane wyłącznie do miejsca wybranego przez użytkownika. Hasła SSH, wklejone klucze prywatne i hasła kluczy pozostają w pamięci sesji i nie są utrwalane przez ARVION. Skróty poleceń zapisują lokalnie tekst podany przez użytkownika. Dane parowania Agenta są szyfrowane kluczem AES-GCM w Android Keystore. Dostęp do sejfu Wi-Fi ma dodatkową bramkę systemowego uwierzytelnienia i ochronę zrzutów; klucz szyfrujący nie wymaga biometrii przy każdej operacji kryptograficznej. Kopiowane hasło jest oznaczane jako poufne, jeśli system obsługuje tę flagę, i usuwane po 30 sekundach tylko wtedy, gdy nadal jest bieżącą zawartością schowka.

Opcjonalna blokada terminala używa biometrii lub kodu blokady urządzenia. Dane biometryczne obsługuje Android; ARVION ich nie odczytuje. Aktualizacja rejestru producentów w Windows łączy się z IEEE tylko na żądanie użytkownika.

Odbiorcy zewnętrzni i ochrona danych Publiczne testy połączenia, DNS/DoH, zapytania o IP/domeny, aktualizacje producentów i transfery uruchomione przez użytkownika wysyłają żądania do odpowiednich serwerów. Serwery otrzymują publiczny adres IP i treść żądania potrzebną do wykonania operacji. ARVION nie sprzedaje lokalnych wyników skanowania i nie przesyła ich do chmury ARVION. Użytkownik decyduje o połączeniach i danych przesyłanych do wybranych hostów. HTTPS, SSH/SFTP i przypięty certyfikat TLS Agenta zapewniają ochronę transmisji tam, gdzie są obsługiwane; Telnet i wybrane lokalne narzędzia HTTP nie szyfrują połączenia. Raporty mogą zawierać identyfikatory sieci, dlatego należy świadomie je udostępniać.

Polityki dostawców: Google, Cloudflare, M-Lab i IEEE. Inne usługi wybrane przez użytkownika stosują własne zasady. W przypadku kontaktu e-mail deweloper otrzymuje adres nadawcy oraz przesłaną treść i załączniki. Dane służą do odpowiedzi i wyjaśnienia zgłoszenia. Można poprosić o usunięcie korespondencji, gdy nie jest już potrzebna, z uwzględnieniem obowiązków przechowywania wynikających z prawa.
